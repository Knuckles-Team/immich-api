# CONN-IMMICH-API — Requirements

Governing specification: [spec.md](spec.md).

Each row identifies one connector behavior and its verification target.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-IMMICH-API-R001` | **Credential references.** The connector must resolve authorized credential references in `immich_api/auth.py` when a client is requested. | `tests/test_auth.py::test_client_resolves_reference_and_cleans_up` must observe reference resolution and resource cleanup. |
| `CONN-IMMICH-API-R002` | **Bounded API requests.** The connector must enforce origin, TLS, timeout, and response-size limits in `immich_api/openapi_runtime.py`. | `tests/test_api_wrapper.py` must exercise rejected origins, redirects, deadlines, and oversized responses through the real client. |
| `CONN-IMMICH-API-R003` | **MCP registration.** The connector must register its operation router through `immich_api/mcp_server.py` and `immich_api/mcp/__init__.py`. | `tests/test_immich_mcp_validation.py::test_mcp_instance_registration` must construct the production server without vendor requests. |
| `CONN-IMMICH-API-R004` | **Native content contracts.** The connector must publish packaged prompts, skills, ontology, and its manifest through `immich_api/mcp_server.py`. | `scripts/generate_tool_schemas.py --check` must validate live tool contracts. `tests/test_immich_content.py::test_native_prompt_skill_shapes_and_tool_discovery` must render prompts and read the declared content through the production SDK server. |
| `CONN-IMMICH-API-R005` | **Typed source observations.** The connector must submit authorized source observations through the shared ingest service in `immich_api/kg_ingest.py`. | `tests/test_kg_ingest.py::test_ingest_uses_scoped_binding_and_preserves_receipt` must observe typed changes at the submission boundary. |
| `CONN-IMMICH-API-R006` | **Complete source parity.** Every operation in the pinned provider schema must retain its method, route, typed arguments, responses and authorization metadata and be reachable through both the API client and native MCP. | `tests/test_operation_parity.py` must execute all source operations against mocked HTTP, verify exact request and response contents, require modern MCP confirmation for writes, and fail on missing or duplicate successful operation IDs. |
| `CONN-IMMICH-API-R007` | **Fleet name.** `pyproject.toml` declares `immich` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `immich`. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. | Every connector name in the package is `immich`. |
| `CONN-IMMICH-API-R008` | **Asset tag producer tool.** Subsystem: immich-api served tools (new spec in immich-api). Add `immich_api/media_tags.py` and register the read-only tool `immich_asset_tags(asset_id)` through the SDK producer contract. It returns the tags that the library's own classifier stored for the asset, with `origin` set to `extracted`. `producer_id` is `immich-ml`, and `producer_revision` is the server version plus the classifier model name. The tool declares `image` and `thumbnail` as modalities. It reads only assets the caller may read. Depends on: SCION-SOURCE-INGEST-R016.3. | Test: `tests/test_media_tags_tool.py::test_tool_returns_extracted_tags_with_revision` (L3). A served test uses a recorded library response and asserts origin, revision and access. |
| `CONN-IMMICH-API-R009` | **Pilot phases I0 to I6 (rollup).** Subsystem: connector pilot. The pilot proves the connector contract on a photo library with a recorded fixture. Children `.1` to `.7` are phases I0 to I6, in order. A phase lands only when the earlier phase verifies. Medulla keeps the mappings (`MEDULLA-UNIFIED-DATA-PLANE-R005`) and entity links (`MEDULLA-UNIFIED-DATA-PLANE-R030`). This connector holds the client, tools and ingest. Depends on: CONN-IMMICH-API-R005, CONN-IMMICH-API-R006. | Closes when `.1` to `.7` verify. Root journey: `tests/test_pilot_phases_served.py::test_phases_run_in_order_against_recorded_library` (L3). |
| `CONN-IMMICH-API-R009.1` | **Phase I0: version-pinned OpenAPI client.** Subsystem: client. Caller: every tool handler in `immich_api/mcp_server.py` → `immich_api/openapi_runtime.py`. The runtime holds the pinned schema `immich_api/openapi_contract.json` and its digest `SOURCE_SHA256` of `immich_api/album_metadata.py`. On the first request of a client it reads the server version through `immich_api/api/api_client_system.py`. It compares major and minor with the pin. A difference refuses with `SERVER_VERSION_UNPINNED` and sends no data request. Writes: none. Depends on: CONN-IMMICH-API-R002, CONN-IMMICH-API-R006. | Test: `tests/test_version_pin.py::test_unpinned_server_version_refuses_before_data_request` (L3). It runs a recorded server at a newer minor version and asserts the code and zero data requests. |
| `CONN-IMMICH-API-R009.2` | **Phase I1: read-first tools.** Subsystem: served tools. Caller: arbora MCP → tool surface of `immich_api/mcp_server.py`. The read tools for assets, albums, people and libraries are registered first. They pass the parity test of R006 before any write tool is exposed. Each read tool carries the read-only hint. Page size comes from config key `IMMICH_PAGE_SIZE`, default 100, range [1, 1000], unit items. An out-of-range value refuses with `PAGE_SIZE_INVALID`. Writes: none. Depends on: .1, CONN-IMMICH-API-R003, CONN-IMMICH-API-R006. | Test: `tests/test_read_tools_served.py::test_read_tools_return_pages_and_refuse_bad_page_size` (L3). It lists albums through the production server against a recorded library. |
| `CONN-IMMICH-API-R009.3` | **Phase I2: approval-gated writes.** Subsystem: served tools. Caller: arbora MCP → write tools of `immich_api/mcp_server.py`. Each write tool carries the destructive hint and needs the confirmation step of the SDK tool surface. An unconfirmed call refuses with `CONFIRMATION_REQUIRED` and sends no request. The connector never approves a call. Admission and approval stay with arbora. Writes: the library, only after confirmation. Depends on: .2, CONN-IMMICH-API-R006. | Test: `tests/test_write_confirmation.py::test_unconfirmed_write_sends_no_request` (L3). It calls one write tool unconfirmed and then confirmed against a recorded library. |
| `CONN-IMMICH-API-R009.4` | **Phase I3: incremental ingest by cursor.** Subsystem: ingest. Caller: SDK connector-sync runner → `immich_api/kg_ingest.py::ingest_album_metadata` → new `ingest_changes(cursor)`. The function asks the library for assets with `updatedAfter` set to the stored cursor. It pages in the page size of .2. The cursor becomes the largest `updatedAt` seen after the SDK accepts the submission. A failed submission leaves the cursor unchanged. Writes: source observations through the shared ingest service. Depends on: .1, CONN-IMMICH-API-R005. | Test: `tests/test_incremental_ingest.py::test_cursor_advances_only_after_accepted_submission` (L3). It ingests two pages and then a failed submission and asserts the cursor. |
| `CONN-IMMICH-API-R009.5` | **Phase I4: no-op replay.** Subsystem: ingest. Caller: `immich_api/kg_ingest.py::ingest_changes` of .4. Each asset carries a content digest, SHA-256 over the canonical JSON of its mapped fields. A replay of a page with unchanged digests submits zero changes. The submission receipt reports no changed record and the cursor stays. A changed field changes the digest and submits one change. Writes: none on a no-op replay. Depends on: .4. | Test: `tests/test_incremental_ingest.py::test_replay_of_unchanged_page_submits_nothing` (L3). It replays one page twice, then edits one field and asserts one change. |
| `CONN-IMMICH-API-R009.6` | **Phase I5: health check tool.** Subsystem: served tools. Caller: arbora fleet health probe → read-only tool `immich_health` in `immich_api/mcp_server.py`. The tool pings the server and reads its version. It returns `ok`, `server_version`, `pinned_version` and `schema_digest`. An unreachable server refuses with `LIBRARY_UNREACHABLE`. Writes: none. Depends on: .1. | Test: `tests/test_health_tool.py::test_health_reports_versions_and_refuses_unreachable` (L3). It runs the production server against a recorded library and a dead address. |
| `CONN-IMMICH-API-R009.7` | **Phase I6: upgrade digest check.** Subsystem: served tools. Caller: operator through arbora MCP → read-only tool `immich_upgrade_digest` in `immich_api/mcp_server.py`. The tool compares the digest of the server's published schema with `SOURCE_SHA256`. It lists the operation ids added and removed. It returns `match` or `mismatch` with both counts. It never changes the pin. A new pin needs a reviewed change that passes the parity test of R006. Writes: none. Depends on: .1, .6. | Test: `tests/test_upgrade_digest.py::test_mismatch_lists_added_and_removed_operations` (L3). It compares a recorded newer schema with the pin and asserts the lists. |
